# harness：仿真时钟上的规划器–执行器运行时

## 问题

HPE 与 MemER 要在同一个运行时里比较：同样的环境、执行器、规划器，只换 harness；规划器的决策延迟 L 可以注入固定值，也可以用实测值；同步与异步两种协议都要支持。时间按仿真时钟走，结果可复现，与机器快慢无关。

## 结构

| 文件 | 职责 |
|---|---|
| `records.py` | 数据类型：观测、动作块、规划器快照与结果、每次调用与每个动作块的日志、回合结果 |
| `protocols.py` | 接口：`Env`、`Executor`、`Planner`、`LatencySource`、`TriggerPolicy` |
| `triggers.py` | 何时发起规划器调用：固定周期（HPE）、上一次生效后立即发起（MemER）、子任务边界到达时（标注规划器） |
| `latency.py` | L 从哪里来：注入的固定值，或规划器报告的实测时间 |
| `runtime.py` | `Runtime`：一个回合的事件循环，同步或异步 |
| `jsonl_log.py` | 把回合结果写成 JSONL |
| `qwen_backend.py` | 规划器模型：HF 官方 Qwen3.8-27B（FlashRT NVFP4），一次图文对话请求，思考可开可关，解码到 EOS 即停，返回各阶段实测时间 |
| `memer_memory.py` | MemER 的关键帧记忆：候选帧一维单链聚类，每簇取下中位，保留最近 8 个（按论文描述实现，未复制 MemER 代码） |
| `memer_prompt.py` | MemER 的零样本提示词（子任务词表、关键帧定义、输出格式、提前量）与回复解析 |
| `memer_planner.py` | MemER 高层作为 `Planner`：最近 8 帧 + 记忆帧 → 当前子任务与新关键帧；解析失败或词表外时保留当前指令 |
| `toy_world.py` | 用于检查运行时的玩具环境、执行器与标注规划器 |
| `check_runtime.py` | 观测式检查：L = 0 时同步与异步一致；玩具环境上 SR、用时随 L 的变化 |

状态归属：仿真时钟、待生效的决策、当前指令、动作块队列都只由 `Runtime` 持有；规划器的内部状态（子目标列表、关键帧记忆）由各自的 `Planner` 实现持有。

## 流程

每个控制步（仿真时间 `dt`）：

1. 若规划器空闲且触发策略要求，就取一个快照（时刻 t₀、观测历史），调用规划器，得到结果和 L：
   - 异步：结果在 t₀ + L 生效，期间执行器继续按旧指令执行；
   - 同步：环境停住，时钟前进 L，结果立即生效。
2. 若有待生效的决策且已到生效时刻，就把它设为当前决策（L = 0 时在同一步生效，所以 L = 0 的同步与异步完全一致）。
3. 动作块用完时，执行器按当前指令出一个新动作块；新指令不打断正在执行的动作块。第一次用上某个决策的时刻记为该决策的"首次使用时刻"。
4. 执行动作块里的下一个动作，时钟前进 `dt`。

环境的步数上限只计执行器实际执行的控制步；同步协议下等待的时间计入仿真时钟但不计步数，需要按时间截止时给 `Runtime` 设 `max_time_s`。

一次只有一个规划器调用在途；在途期间到期的周期触发顺延到它生效之后。L 的定义：从快照时刻到执行器首次使用该决策的时刻，日志里同时记下快照、生效、首次使用三个时刻。
