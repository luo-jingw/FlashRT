# RoboCerebra 上的 HPE 与 MemER 对比：任务单

## 目标

在同一套 RoboCerebra 任务、同一个执行器、同一个规划器模型上比较两种 harness，回答主线问题：异步下规划器的决策延迟 L 怎样影响任务质量。

- 基线：RoboCerebra 论文 §4 的 HPE（开始时把任务拆成子目标，之后周期监控，遇到完成或偏离就更新子目标）。
- 对照：MemER（每次调用输入最近帧和检索出的关键帧，输出当前子任务和新的关键帧）。
- 两者唯一的差别是 harness；规划器都用 HF 官方 Qwen3.8-27B，零样本；执行器是同一个 checkpoint。

## 固定的设置

| 项 | 取值 |
|---|---|
| 规划器 | HF 官方 `Qwen/Qwen3.8-27B`（FlashRT NVFP4）。不使用任何其他权重 |
| 环境 | RoboCerebra 代码与评测集：[qiuboxiang/RoboCerebra](https://github.com/qiuboxiang/RoboCerebra)、[RoboCerebraBench](https://huggingface.co/datasets/qiukingballball/RoboCerebraBench) |
| 训练数据 | [RoboCerebra 数据集](https://huggingface.co/datasets/qiukingballball/RoboCerebra)，1 000 条人工标注轨迹 |
| 时间 | 质量实验一律用仿真时间（按控制步计），不用墙钟；Thor 上实测的 L 事后标到曲线上 |
| L 的定义 | 从规划器取观测快照的时刻，到执行器第一次用上这个决策的时刻（仿真时间） |
| 指标 | SR；子任务完成率（完成的子任务数 / 总子任务数）；完成步数；SCT = 成功 × 最短步数 / max(实际步数, 最短步数)，最短步数取 L = 0、标注规划器下同一回合的步数 |

## Chenwei 的任务

每个任务完成后交回"交付"一栏里的文件；遇到"停止条件"就停下并报告，不要自行换方案。

### C0：环境与数据摸底

- **目的**：确认能在 RoboCerebra 上训练和评测一个按子目标指令执行的策略。
- **做法**：在 Chenwei 那台 Thor 上 clone 代码仓库，下载数据集和评测集，读 `evaluation/` 与数据文件，不训练、不改代码；装好仿真环境，跑通一个评测回合（任意动作即可）。
- **交付**：`C0_report.md`，按下表逐项填写，每项附文件名与行号或数据字段名作为依据：

| 要查的项 | 示例 |
|---|---|
| 数据格式 | RLDS / LeRobot / HDF5；字段列表 |
| 子目标标注 | 字段名；每条轨迹的子目标数；子目标起止步是否给出；子目标文本举例 3 条 |
| 控制频率、动作空间、相机 | Hz；动作维度；相机名与分辨率 |
| 评测集的任务类型与回合数 | Ideal、记忆探索、记忆执行、随机扰动、观测不一致、混合，各多少回合；每回合步数上限 |
| 成功判定 | 整体成功与子任务成功分别怎么判 |
| `eval_openvla.py` 的接口 | 输入什么、每步怎样拿到指令、能否在回合中途换指令 |
| 可用的训练代码 | 仓库内是否有；依赖的 OpenVLA-OFT 版本 |
| 仿真能否在 Thor 上运行 | 安装中改过什么；跑一个回合的用时 |

- **验收**：表中每项都有依据；查不到的写"未找到"，不要猜。
- **停止条件**：数据集里没有子目标的时间标注；评测代码不支持回合中途换指令；仿真在 Thor 上跑不起来。

### C1：训练按子目标指令执行的执行器

- **目的**：得到一个读子目标指令的约 4B 执行器。
- **做法**：
  1. 按 C0 查到的格式，把每条轨迹按子目标的时间标注切成"子目标指令 + 对应片段"。
  2. 模型从 π0.5、ImageWAM 或其他约 4B 的 VLA / WAM 中选一个，HPE 与 MemER 两边统一用它；在 Chenwei 那台 Thor 上训练和运行。
  3. 训练集只用 RoboCerebra 训练数据，不混入评测集。
- **交付**：checkpoint 路径；`C1_train.md`（配置、步数、用时、loss 曲线图、数据切分统计：子目标条数、平均长度）。
- **验收**：训练 loss 收敛；在 3 个训练集子目标上回放，能完成至少 1 个（只做冒烟检查）。
- **停止条件**：Thor 上训练跑不起来；数据转换后子目标片段少于 1 000 条。

### C2：门槛测试（决定是否继续）

- **目的**：确认执行器读子目标指令，且整体能力足够画出曲线。
- **做法 A，换指令测试**：从评测集 Ideal 类取 5 个任务，每个子目标跑 4 组，各 10 回合，种子一一对应：
  - 原子目标指令；
  - "stay still and do not move"；
  - 另一个任务的子目标指令；
  - 空字符串。
  设计参照 `experiments/robotwin_instruction/`（同样的四组、同样的种子对齐方式）。
- **做法 B，能力测试**：L = 0、标注规划器（子目标按标注顺序给，上一个完成立刻给下一个），Ideal 类 10 回合。
- **交付**：`C2_report.md`，两张表：A 的成功率（任务 × 四组）；B 的 SR、子任务完成率、平均步数。附每组 1 段视频。
- **门槛**：
  - A：原指令下成功率明显高于另外三组（另外三组多数降到原来的一半以下）；
  - B：子任务完成率 ≥ 30 %。
  两条都满足才进入 C3、C4；否则报告数字后停止。

### C3：复现 HPE 基线

- **前提**：C2 通过；J1、J2 已交付。
- **做法**：在 J1 的运行时上实现 HPE：
  1. 回合开始调用一次规划器，把任务指令拆成子目标列表（输出格式：JSON 数组）；
  2. 之后每 Δ 个仿真秒调用一次规划器，输入当前画面、子目标列表、当前子目标，输出 `continue` / `next` / `replan`（JSON）；
  3. `next` 切到下一个子目标，`replan` 重新拆分剩余部分。
  提示词写在单独的文件里，逐字附在交付中。Δ 先取 5 s。
- **交付**：代码；提示词文件；Ideal 类 10 回合的 SR、子任务完成率、每次规划器调用的日志（按 J1 的格式）。
- **验收**：日志字段齐全；解析失败率（JSON 解析不出来的调用占比）单独报告。
- **不要做**：不要微调规划器；不要换规划器模型。

### C4：标注规划器 + 注入 L

- **前提**：C2 通过；J1 已交付。
- **做法**：在 J1 的运行时上，子目标按标注顺序给出，但每个子目标在边界到达后延迟 L 才交给执行器：
  - L ∈ {0, 0.5, 1, 2, 3, 4, 6, 8} 秒（仿真时间）；
  - 同步与异步各一组：同步时执行器在 L 期间停住；异步时执行器继续执行旧子目标；
  - Ideal 类与记忆类各 10 回合，每个 L 用同一组种子。
- **交付**：一张表（L × 同步/异步 × 任务类型 → SR、子任务完成率、平均步数、SCT）和原始日志。
- **验收**：L = 0 的同步与异步结果一致（同一决策、同一时刻，应当相同）；不一致先报告原因。

## Jingwu 的任务

### J1：共用的异步运行时与日志格式

- 仿真时钟上的事件调度：规划器在 t₀ 取快照，结果在 t₀ + L 写入"当前决策"；执行器在下一个动作块边界读取。L 可注入固定值，也可用实测值。
- 同步模式：执行器在 L 期间停住。
- 日志：每次规划器调用记录快照时刻、发出时刻、生效时刻、L、输入 token 数、输出文本、解析结果；每个动作块记录时刻、所用子目标、执行器时延。
- 交付给 Chenwei：接口说明、一个最小示例（标注规划器 + L = 1 s）。

### J2：规划器服务

- FlashRT 上的 HF 官方 Qwen3.8-27B（NVFP4），支持图像输入、思考开或关；返回文本与实测的 prefill、decode 时间。
- 跑在 Thor 上；质量实验里 L 用注入值，所以规划器本身的快慢不影响质量曲线。

### J3：MemER 移植到 RoboCerebra

- 复用 MemER 的记忆模块与输出解析；提示词改为零样本版本：给出子任务词表（取自 RoboCerebra 标注）、关键帧定义、输出格式。
- 解析失败时保留上一个子任务。

### J4：HPE 与 MemER 的质量对比

- 变量：harness（HPE、MemER）× 协议（同步、异步）× L（注入）× 思考（开、关）。
- 指标同上；先用 Ideal 与记忆类。

### J5：Thor 上实测 L

- HPE 与 MemER 的真实调用，在 Thor 上与执行器共置，测 L 的分布；按 SM 分配、上下文长度、思考模式分档。
- 把实测的 L 标到 J4 和 C4 的曲线上。
